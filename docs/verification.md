# MVP verification notes

The application uses deterministic synthetic fixtures; no real operational records are part of the repository. The main browser test uses the real API and a migrated SQLite database. It exercises sample loading, exact rule counts, source evidence, saved review after refresh, CSV export, valid and invalid custom uploads, mobile navigation, and the evidence drawer. The automated accessibility scan checks the overview, import, and evidence screens against WCAG 2 A/AA and 2.1 A/AA rules; keyboard and visual checks remain necessary because automated scans cannot prove full accessibility.

Local bounded-capacity measurement on 30 September 2026: Windows, Python 3.13.3, SQLite, FastAPI `TestClient`, and a temporary migrated database. A synthetic submission of exactly 10,000 combined records (100 assets, 4,900 alerts, 5,000 cases) took **0.64 seconds to import** and **0.14 seconds to assess**. This is one warm local measurement, not a cross-machine service-level guarantee. The measured dataset produces three `no_signal` results. The code enforces 10,000 combined rows, 10 MiB of CSV content, and an 11 MiB HTTP request envelope.

Run the checks from a source checkout with `cd backend && .venv/Scripts/ruff check . && .venv/Scripts/pytest -q` on Windows (use `.venv/bin/` on POSIX), and `cd frontend && npm run typecheck && npm test && npm run build && npm run test:e2e`. The browser suite expects the backend on port 8000 and Vite on port 5173 outside CI; CI starts both against its own migrated temporary database. For a local Chrome installation, set `PLAYWRIGHT_CHANNEL=chrome` before the browser suite.
